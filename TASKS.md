## Design — numbered pieces (status: `[ ]` not started · `[x]` done · `[!]` blocked)

- [x] **1.** Explorations: list (the feedback branch is hidden: switching to it would swap in a stale snapshot), start (create then switch) and switch, telling the writer that switching saves the page first and changes the project's files.
- [x] **2.** Tags: "Name a Version" (any of the recent versions, optional note); tag names show on the version list.
- [x] **3.** Merge: bring an exploration into the current one; on a conflict stop, name the files in plain words, and say nothing changed.
- [x] **4.** Annotations as marks, per `docs/ANNOTATION_FORMAT.md`: branch name from the setting, the D15 locate chain in TypeScript (exact matching, code-point offsets converted for marks; shared test vectors generated by the Python tests), marks re-set after saves, Accept/Reject as new commits on the feedback branch.
- [x] **5.** Sync over HTTPS: connect form (address + token), token only in `api.secrets`, never in settings, logs, views or notices; `api.notify` after a sync.

Each command and surface gets a test on `createFakeHost`; every `src/*.ts` has a matching `*.test.ts`.

Inputs from queue 2: the format spec is `docs/ANNOTATION_FORMAT.md`; `interop/lib.mjs` is a working JS reader of it and `interop/write-repo.mjs` shows `api.history`-style writing (same-tree commit with a YAML body). Offsets and context lengths count Unicode code points (use `Array.from`), line numbers are 0-indexed, and locate ties go to the match nearest the stored offset, then the stored line. Veneer's `createBranch` and tag creation accept only ASCII letters, digits, `.`, `_`, `-` and `/`, while GitWrite accepts any valid git name. A conflicting merge in the GitWrite CLI leaves `MERGE_HEAD` behind, which Veneer does not detect: check for it before saving.
